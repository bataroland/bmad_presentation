A javax.crypto csapda

Naiv megközelítés

sed -i 's/javax/jakarta/g' *.java

javax.crypto → jakarta.crypto

javax.net.ssl → jakarta.net.ssl

BROKEN CRYPTO. BROKEN TLS.

BMAD megközelítés

PRD FR6 explicit kimondja:

"JDK-owned packages
(javax.crypto, javax.net.ssl)
must NEVER be renamed"

Tervezési fázisban felderítve.
Nem production-ben.

"EZ a BMAD lényege. A Pre-mortem Analysis-ben derült ki. Ki csinált volna find-and-replace-t? Legyetek őszinték."

A kód diff — tiszta, fázisonkénti

Before

import javax.persistence.*;

@Temporal(TemporalType.DATE)
private Date publishedDate;
private Date createdAt;

new Comparator<Book>() {
  public int compare(Book b1, Book b2) {
    return b1.getAuthor()
      .compareTo(b2.getAuthor());
  }
}

After

import jakarta.persistence.*;

private LocalDate publishedDate;
@JsonFormat(pattern="yyyy-MM-dd'T'HH:mm:ss")
private LocalDateTime createdAt;

Comparator.comparing(Book::getAuthor)
